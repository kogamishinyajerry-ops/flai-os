# GLM 生长烟测（Growth Smoke Test）· Spec v1

- **状态**：Approved（owner 2026-07-13「开工」；源=战略共识七问逐决）。
- **地位**：封板双判据之判据②的执行契约。骨架「完成」的可证伪定义 =
  ①**结构完成**：连续 2 个新模块类接入内核零 diff（只加 agents/tools/evals 包，不碰 backend/app；git 可直接度量）；
  ②**生长完成**：本烟测达 A 级。
  两判据都过 = 骨架封板，具备内网导入的「完成体」资格（滩头侦察版可先行，见战略共识第 6 条）。
- **性质**：测量，不是开发。烟测全程零内核改动；产出是死点报告，不是功能。

## 一、命题

内网的生长者不是 Claude/Codex，是 GLM + 轻量 harness。「骨架导入内网后会自动生长」这一核心宣称，
等价于可证伪命题：**弱模型只凭仓内文档与契约，能否独立长出一个合格的新 Agent 包。**
文档写得再好，GLM 举不动 = 生长层未完成。

## 二、被试与环境

- **模型**：GLM-5.1（与 FLAI_LLM_* 同配置源；key 走环境变量注入，不入沙箱文件、不入任何记录）。
- **harness**：OpenCode（内网入口的忠实模拟，与 COMAC_FDE 着陆包 AGENTS.md 同源）。本机未装则先装。
  **禁用 Claude/Codex/其他模型**；GLM 触 5h coding 限额 = 暂停等窗口恢复，**不换 Minimax**（换模型即破坏「内网唯一模型」前提）。
- **沙箱**：flai-os 干净 worktree/clone @ 固定 commit，仅移除本 spec 文件与既有烟测结果目录（内网交付的是完整仓，
  ADR/reviews/docs 同事都看得到，故其余一律保留）。数据库用临时库，绝不指向 data/ 真库；后端/worker 用空闲端口，不与 8620 争用。
- **记录**：全程 transcript + 澄清对话逐字存档 `docs/reviews/glm-growth-smoke-r<N>/`（主仓，沙箱外）；OpenCode 与 GLM 版本号记录在案。

## 三、任务（需求文本冻结，测前不改）

D 簇型（数据计算出图簇的无图变体）合成需求，交给 GLM 的原文：

> 我们组每次台架试验后拿到一份测点 CSV（第一列时间 s，后面若干通道列数值）。现在要人工算每个通道的
> 均值/最大值/最小值/超限次数（限值另有一张 CSV：通道名、下限、上限），再手写一段试验小结。
> 希望平台上有个智能体：我提交测点 CSV 和限值 CSV，它自动算统计、判超限、生成一页小结草稿，我审核签发后使用。

**样例数据**（随需求一并提供，测前用带种子脚本生成，格式冻结）：
`bench_points.csv`＝`t_s,CH1,CH2,CH3,CH4` 共 200 行合成数据（含 2 个通道各若干次越限）；
`bench_limits.csv`＝`channel,lower,upper` 4 行。全部虚构，零真实工程数据。

**合格产出**（= 平台既有 L0 注册线，不新设标准）：
1. 完整 Agent 包落 `agents/<id>/`（agent.yaml 五件套齐全，过契约 gate 与 registry 校验）；
2. 所需工具落 `tools_impl/`（预期 stdlib csv 即可，**不引入新依赖**——若 GLM 自行引入，记录为观察项）；
3. ≥1 个 eval case（draft 即可，L0 线不要求晋升）；
4. 起服后全链可跑：create_task → execute → waiting_review → 人签 completed（确定性执行即可，不强制 LLM 调用；
   category/profile 由 GLM 自行依文档裁定——这本身是测点）。

## 四、约束的操作定义

- 输入 = 沙箱仓 + 上述需求原文 + 两个样例 CSV，**没有别的**（不给本讨论/memory/口头补充知识）。
- 人肉澄清 ≤3 次：主控只扮演「提需求的同事」，可答业务语义（如"超限算次数还是算时长？"），
  **绝不代写代码、绝不指文件路径、绝不解释平台机制**。每次澄清逐字入档。
- 主控在 GLM 工作期间不干预；仅在其明确宣告完成或放弃后进入判分。

## 五、判分

- **A**＝合格产出四条全达成（允许用满 3 次澄清）。
- **B**＝部分走通：记录推进到哪一步 + 死点清单。
- **C**＝起步即死：无法定位从哪开始。

**死点分类学**（每类死点映射一块确定的脚手架工作，这是烟测的真正产出）：

| 类 | 现象 | 映射的脚手架 |
|---|---|---|
| D1 文档层 | 找不到/读不懂该读的文档 | 面向 agent 作者的入口指南（仓内 AGENTS.md/authoring guide） |
| D2 契约层 | agent.yaml/schema 写不对、过不了 gate | `flai new-agent` 生成器/模板 |
| D3 验证层 | eval case/测试不会写 | eval 模板与最小示例 |
| D4 运行时层 | 报错读不懂、排错原地转 | 错误信息人话化 |
| D5 流程层 | 知道做什么但顺序/命令错 | 步骤化 checklist（注册→起服→验收） |

死点记录格式：现象（逐字引 GLM 卡点）/ 判层 / 对应脚手架条目。

## 六、通过线与复测协议

- 生长完成判据 = **A 级**。
- **首轮预期就是 B/C——那不是失败，是测量成功**：死点报告即下一块磨刀石的施工单。
- 复测：每补齐一层脚手架后可重跑（全新会话）。**第二轮起更换需求文本**（同为 D 簇、同难度）防对题库过拟合；
  样例数据每轮重新生成。
- 与判据①的关系：死点映射的脚手架多数落在 docs/scripts/模板层，本身应零内核 diff；
  **若某死点必须改内核才能解，它就是真骨架缺口**，进锻打队列（现队列：协作运行时 / 角色轴 / 知识回写；
  FEA 刻意留作判据①的零 diff 验证弹）。

## 七、诚实边界

- 外网 GLM（bigmodel.cn）≠ 内网 GLM 部署形态（是否 OpenAI-compatible 仍是 M4 最大未验假设）。
  本烟测只验证**生长层**，不验证**环境层**；环境层归滩头侦察（docs/M4_intranet_day1_recon_checklist.md）。
- harness 差异（OpenCode 版本/工具集）会影响结果，逐轮记录版本；判分由主控执行但 transcript 全量存档，判分可复核。
- 烟测结论的宣称上限：「GLM 在模拟条件下长出/长不出 Agent 包」——不外推为「内网一定能/不能自动生长」。
