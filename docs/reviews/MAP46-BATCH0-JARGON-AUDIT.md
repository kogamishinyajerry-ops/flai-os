### P0-1 非航空通用任务零执行面——Destination「走通一个通用任务」当前不可能达成

事实：16 个 Agent 包全部航空/工程向（清单见 traces/static_copy_inventory.md §8），
无任何通用执行型能力（写脚本/整理表格/翻译/文档）。通用任务请求的真实归宿只有三条：
通识直答（概念类）、refuse 登记（任务类）、或被误路由进航空 Agent（prompt 以
「重新解释本身就是信号」条款防此，#42 钉字面）。实测「帮我写一个 Python 脚本，把手上的
Excel 表格整理成周报。」（b1）：stub 栈上只能演示壳层追问流；真实裁决未验证（stub 不裁决）。
对照 Destination 终点验收「非航空通用场景首轮会话零行话摩擦**走通一个通用任务**」——
当前 Agent 清单下该验收不可达成。
裁决候选（owner 裁，详见 §四-3）：A=接（新增通用 Agent 包样板，走既有契约）；
B=不接（通识直答给指导不执行+refuse 登记闭环强化）；C=范围待定（先定「商业级」边界再定能力面）。

### P0-2 首轮行话墙 + 零引导——「零行话摩擦」在登录后第一屏即破

事实（a1/a2 截图+留痕）：
- 登录门首句 `机器提议，人签发。`（WelcomeGate.vue:8）——「签发」未解释即上首屏；
- 第一屏 hero `说说你要做的工程活儿` + `系统会在后台自动编排所需能力` + composer 政策句
  `系统会在后台准备方案 · 开工与签发仍由你确认`（GuidePage.vue:11/13/586）——
  工程/编排/方案/开工/签发 五词首屏同现，对照「Claude/Codex/Workbuddy 风格=通用直白」均有摩擦；
- OnboardingCard.vue **零引用=死代码**（grep 无 import）——新用户无示例提示、无能力导览、
  无首个任务模板；第一屏除问候与输入框外零引导；

  +`Registry 能力`/`我的 Candidate`/`隔离 Skill 包`/`冷读`/`不晋级`——通用用户零可读。
裁决候选：首轮文案通用化包（价值句/hero/政策句改写，签发归位签发语境）+ 引导形态比选

### P1-1 会话面默认区平台词表：开工/签发/工作段/执行单元/召集/接力

事实：开工 69 处、签发 157 处（全站频次见 traces §7）；方案卡主 CTA `按方案开工`+
政策句 `开工由你确认，产物放行由你批准——签发权始终在你`（b2）；会话轴段头

### P1-2 异常路径文案工程日志风 + 上游错误直通默认面

事实：
- 报错 toast（实测 DOM 捕获）：`流式中断 · 本轮未保存 — 导引本轮对话失败（可重试）：{上游原始错误文本}`
  ——前缀人话，后缀直通 `exc`（conversations.py:204）；真实上游错误（HTTP 状态/超时栈）将原样上屏；
- 任务失败面（c3）：`ModelConfigError: 缺少环境变量 FLAI_LLM_BASE_URL（profile=reasoning 的
  base_url，见 docs/04）`——异常类名+环境变量名+内部文档指针直出默认面，事件时间轴同文复读；
- 对账/锁定态：`创建状态待核，禁止重复开工`、`请用同一操作标识核对`、`禁止换 key 重复开工`、
  `审计血缘会自动保留`、`本轮不落库`（traces §2/§6）——fail-closed 提示是工程日志风，
  出现频率低但出现时正是用户最困惑时。
红线注意：诚实透出（不静默、如实记）是宪法纪律，**不可弱化**；可裁的只是**排版分层**
（人话摘要前置+技术细节进披露），不是删除信息。owner 裁。

### P1-3 空态与统计格治理词无解释（固化 case/晋升/Agent 动态/人签放行）

## 三、范围逐项结论

### 3.1 首轮/新用户体验（登录后第一屏、空态、引导、无任务时的接法）

第一屏（a2）：问候+一句起手+输入框+政策句，零引导零示例；侧栏空态
`还没有对话——从上方「新对话」开始` 给方向（合格）。无任务接法：今日页空态（a3）
分组词均给方向但混治理词（P1-3）；任务台空态（a4）`还没有任务——先在主对话里说明目标` 合格；
状态中心零态（a8）`没有等你签发的任务`+`查看全部任务 →` 合格；⌘K（a5）`搜索会话、任务…`
通用合格。375 首屏无横向溢出（a9 PASS）。**结论：骨架合格，摩擦集中在文案行话与引导缺位
（P0-2/P1-3）。**

### 3.2 会话面词汇（guide 话术/姿态文案/错误拒答/工程术语语境）

stub 边界声明：guide 正文话术（真实模型措辞）本环境不可测——**未验证**；可测的是产品壳文案。
壳层实测（b1-b7）：方案卡/披露区/拒答卡/错误恢复/段结构全部真实渲染，行话分布=P1-1/P1-2。
错误路径三件套实测：上游失败→瞬时 toast（措辞人话前缀+上游直通）+原话退回输入框（b6b，
与慢等待承诺一致）；流式中断→`保存状态待核` 卡；refuse→显式拒绝卡（b7）。
**结论：壳层文案是全站行话最密面，也是「通用化」收益最大面。**

### 3.3 任务台/今日页词汇与发现性（#30 合并后现状）

对照基线 MAP32-DESTINATION-ACCEPTANCE-record.md 复核：C1 同分组同计数同称呼仍成立
（c1/c2/c5 与 API 对账一致）；C2 零待签不渲染摘要仍成立（a3/c1）；C3 一级导航仅 对话/今日
仍成立；#32 留痕会话渲染正常（c6）。新发问题=P2-1/P2-2/P2-4/P2-5；页脚诚实口径两处
（`基于最近 100 条任务窗口`/`窗口外不虚报`）偏技术但属诚实纪律。**结论：#30 合并面稳定，
残余为标题碰撞与裸 id 副行等抛光级问题。**

### 3.4 通识通道现状（#33 第四姿态 + #36 地板句松弛 + #42 Opus 5 条款后）

- 姿态体系源码面完整：第四姿态（通识/概念解释→叙事直答，不输出计划块，不得含数值结论/

   候选规则：路由裁决∈{orchestrate, refuse, 任务事件} → 可信面自动浮现；通识直答 → 纯叙事
   +批准/授权面地板句常驻（现状）。是否给通识直答加轻标识（P2-8）随此定稿。
3. **非航空通用任务接不接**（绑 P0-1）：
   - 候选 A=接：新增通用执行样板包（脚本/表格/翻译），走既有 Agent Package 契约与签发闸，
     信任色/诚实纪律不变；
