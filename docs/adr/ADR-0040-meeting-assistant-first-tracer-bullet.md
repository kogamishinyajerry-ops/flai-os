# ADR-0040：会议行动助手首个薄切片采用会后纪要与行动项整理

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0016、ADR-0034、ADR-0037

会议行动助手的第一个完整 tracer bullet 是“会后纪要与行动项整理”。协调人员在会议结束后主动提交会议笔记、已有文字转写稿、议程和相关文本型附件；系统自动生成带来源锚点的会议工作包草稿，区分议题、决策、共识、未决问题和责任事项，并集中列出来源冲突、内容推断和责任字段缺失等待确认例外。

每项责任事项必须具有预期产出、唯一负责人、截止时间、验收标准和验收人。来源材料没有明确给出时，系统不得把模型推断静默写成组织事实；协调人员只在末端处理聚合例外。Phase 0A 只允许会议负责人确认隔离测试命名空间中的精确版本，产生明确标记的 `SYNTHETIC/TEST` receipt，不创建正式记录 ID、不激活真实责任、不触发外部写入。只有 R6 真实路径验证完成并进入获批的 Phase 0B 范围后，具名会议负责人对真实材料签发，才可形成正式会议记录和生效责任事项。AI 不签发会议结论，也不代替验收人关闭责任事项。

首版不做实时录音或语音转写、不自动加入在线会议、不发送邮件或群通知、不自动催办升级，也不实现成果提交和责任事项验收的完整后续生命周期。智能办公助手可以润色普通纪要文本，但只有本工作流产生结构化来源、例外和人签合同。

选择会后导入而不是实时会议伴随，是为了先在有限输入和明确人类责任下验证多文档来源锚定、结构化提取、例外审阅、测试签发合同和 Delivery Bundle，再在 R6 验证真实组织事实路径；避免把语音识别、身份识别、通知连接器与行动跟踪一次性混入首个薄切片。

本 ADR 决定产品薄切片，不授权当前混合工作树上的实现。正式开发前仍需固定首版输入格式、来源锚点粒度、会议负责人身份与签发资格、责任事项字段合同和无依据推断的 invalid-first fixtures。
