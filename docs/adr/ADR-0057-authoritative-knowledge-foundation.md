# ADR-0057：建立逻辑统一、物理可联邦的权威知识底座

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0015、ADR-0017、ADR-0021、ADR-0050、ADR-0055

FLAi-OS 把企业规章、条款、领导正式要求、决策命令和工程基线视为 Agent 工作的依据层，而不是普通 RAG 语料。现有 Knowledge Scope、密级白名单、来源指纹、零命中拒答和引用能力继续作为内核骨架；在其上补齐权威发布、不可变版本、有效性、适用范围、冲突处理和任务时依据绑定，不另建一套平行知识服务。

权威知识底座是逻辑统一的权威目录和访问通道，底层内容可以物理分布在受控文件目录、文档管理系统、Obsidian Vault 或其他内网系统。Obsidian 只可充当编辑与策展界面，BM25、向量数据库、Embedding 和 Rerank 只可充当检索索引；文件被放入某个目录、被向量化或被模型引用，都不能自动获得权威性。

知识材料必须同时区分权威类别与生命周期。只有由具名授权人员在本平台签发、处于当前有效状态的材料，才能作为组织要求和工程依据；受信源系统只能提供可验证的上游签发 `source_system_attestation`，不能成为 FLAi-OS signer。受控参考材料可以辅助分析，但不得冒充组织命令；普通上传、会议笔记、转写稿、工作草稿和 AI 产物只能作为任务范围内的工作材料。已被替代、撤销或过期的版本只用于历史追溯，不得回答为当前有效要求。会议材料只有经过既定签发流程形成正式记录后，才可能作为权威知识项进入发布评审。

每个已发布知识项至少绑定稳定标识、标题、发布主体、责任人、批准证据、不可变版本、内容摘要、密级、适用对象或工程范围、生效与失效时间、替代关系及来源系统。具体字段名和持久化格式留给实施规格确定，但不得丢失这些语义。修订、补充、更正和撤销通过新版本或状态事件表达，不覆盖既有已发布字节。

所有 Agent 输出中的规章判断、要求复述和工程建议必须形成逐项依据链，至少能够定位到知识项版本、内容摘要和条款、章节、页码、单元格或等价精确锚点，并记录该版本在任务执行时的有效状态。检索相似度只能说明相关性，不能证明权威性或正确性。任务审计记录应能重建当时实际使用的知识版本，不能在源文件后来变化后把新内容冒充为旧任务依据。

检索可以用确定性规则排除已过期或明确被替代的版本；当依据缺失、适用范围不明或多个当前有效来源仍然冲突时，系统必须显示“无法确认”及冲突来源，不得让 LLM 选择一个看起来合理的答案。Agent 可以继续完成安全、只读的分析并把未知项集中进入最终 Delivery Bundle，但不能以默认值或模型常识静默补齐事实，也不能执行依赖这些未决事实的不可逆动作。

CFD 工作流必须把需求、边界条件、模型选择和工程建议分别标记为“权威依据”“工程师确认假设”或“模型建议”。模型建议不能改写为既有要求；缺少来源的边界条件只能作为待确认假设。首个“CFD 算例体检”可以在不中途打断用户的前提下完成只读检查，并在末端一次性呈现依据缺口、冲突和假设清单。

权威性发布、变更、撤销和受限知识访问都属于治理动作：只能由经过认证且具有相应角色的具名人员签发，AI 不得自批。受信源系统只能提供 `source_system_attestation`，证明上游签发事实、来源版本和内容摘要，不能替代本平台的 `human_signer`；无法验证上游真人签发或适用制度时按未知处理。知识密级必须沿现有分类与授权链传播到任务、事件、产物和审计记录，不能因摘要、引用或生成报告而降级。

能力发布包冻结的是 `ReleaseKnowledgeBinding`（允许 scope、版本选择策略、目录根摘要），不是带 actor、任务时刻和实际锚点的运行时快照。每次任务生成独立 `TaskKnowledgeSnapshot` 并证明符合 Binding；Task Snapshot 绑定运行证据，但不得反向改变 release digest。

本 ADR 不决定具体文档管理产品、向量数据库、Embedding 模型或 Obsidian 目录结构，也不授权把真实内网知识立即导入当前混合工作树。实施前必须进一步固定权威类别与生命周期契约、发布与撤销授权矩阵、各文件格式的精确锚点策略、冲突与时间有效性算法、知识版本快照证据，以及普通上传和 AI 产物无法越权晋升的 invalid-first fixtures。
