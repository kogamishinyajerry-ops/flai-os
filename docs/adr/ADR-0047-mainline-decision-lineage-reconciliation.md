# ADR-0047：主线 ADR 谱系与历史 safe-auto 决策对账

- 状态：产品与实施准备方向已接受（委托人在设计会话中确认，2026-07-23；不构成组织签发、试点、发布或上线授权）
- 关联：ADR-0012、ADR-0016、ADR-0019、ADR-0030、ADR-0049、ADR-0050
- 历史证据：`feat/eval-async-queue@567de2dbba643f93f12d251905a64ee72a26c1ae`

当前 main 的 `ADR-0030` 是“专家身份轴与密级/依据契约”。其直接后代 `codex/agent-fact-projection-ui@52c38561af9e77e0f44a8952e61e47f19c76e773` 已形成 `ADR-0031～0046` 的实现谱系，其中 `ADR-0031` 是团队模板、`ADR-0032` 是任务实时快照、`ADR-0046` 是 ax Web Extract。另一条历史 safe-auto 分支却曾用 `ADR-0030～0032` 记录 ax、认证 safe-auto 与版本化 Guide DAG。即使这些分支尚未进入远端 main，已实现决定的编号也不能回收；因此不得把历史 safe-auto 编号直接复制进主线，也不得让 V0.2 决策依赖当前基线无法唯一解析的旧编号。

本 ADR 作出以下谱系裁决：

1. 当前 main 的“专家身份轴与密级/依据契约”继续作为唯一有效的 `ADR-0030`；`ADR-0031～0046` 为已实现后代谱系保留，不能覆盖、回收或被历史 safe-auto 的同号文件替代。
2. V0.2 产品方向统一使用 `ADR-0049～0064`；本 ADR 使用 `ADR-0047`，知识发布身份澄清使用 `ADR-0048`。编号调整只消除冲突，不改变委托人已经接受的产品语义。
3. 历史认证 safe-auto 与版本化 Guide DAG 只作为 `feat/eval-async-queue@567de2d` 的 commit-bound implementation evidence；它们不因曾标记 Accepted 而自动成为当前 main 的适用 ADR，也不能单独授权 Runtime、Schema、网络出口或附件执行。`ADR-0062～0064` 已用于飞书外网研发边界、内外网隔离与 Workspace 产品方向；若未来选择性吸收上述历史实现，必须从当时下一个空闲编号另立实施决定，当前候选编号为 `ADR-0065`，不得复用 `ADR-0063/0064`。
4. ADR-0049、ADR-0050 对历史 safe-auto 的兼容要求由本 ADR 承接。后续选择性吸收时，必须保留确定性计划校验、认证主体与对象范围、不可变输入/来源摘要、幂等回执与恢复、无效输入零副作用、真人唯一签发等不变量；不能整体 cherry-pick 后宣称完成 V0.2 控制内核。
5. 每次实际吸收必须基于最新主线重新审计文件和调用路径，形成独立、无冲号的实施 ADR 或规格，明确目标提交、Schema/API/状态机影响、迁移与回滚、invalid-first fixtures 和验证命令。历史实现与当前目标冲突时，以最新适用 ADR 和当前主线事实为准。
6. 本 ADR 只修复决策谱系和引用关系，不重新批准 ax 联网、不批准历史 safe-auto 扩权、不批准 OpenClaw/OpenHands 依赖，也不授权任何 Git 合并、部署或生产暴露。

因此，当前 main 不存在可直接引用的“ADR-0031 safe-auto 合同”。文档需要表达历史限制时，应引用本 ADR 并明确它是选择性吸收门，而不是把旧分支行为写成当前已实现事实。
