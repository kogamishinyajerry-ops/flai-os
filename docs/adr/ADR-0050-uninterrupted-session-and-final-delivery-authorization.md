# ADR-0050：不中断自治会话与末端交付授权

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0007、ADR-0012、ADR-0016、ADR-0047、ADR-0049

FLAi-OS 不建立通用的中途 Action 审批流。用户提交目标后，控制内核创建受控自治会话；会话范围内的可逆沙箱动作，以及具备明确预算、强制停止、回滚或补偿路径和执行 receipt 的受控工程操作，由 Agent 连续规划、执行、验证和恢复，不要求用户补填 Agent 已推导的字段，也不逐工具、逐命令或逐文件弹窗确认。

对正式工程资产、外部系统或组织事实产生不可逆影响的动作不得作为会话内普通工具直接执行。Agent 只能将其编译为待交付动作，与产物 hash、差异、验证证据、残余风险、策略版本和动作参数共同冻结成 Delivery Bundle；具名真人只在末端对精确匹配的 Bundle 作一次性交付授权。授权必须在执行前重新校验主体与策略，单次 CAS 消费；Bundle 漂移、过期、越权或执行凭据不匹配均 fail-closed。消费授权、创建唯一 DeliveryAttempt 与全部动作意图必须同一事务完成，每个动作绑定跨重试稳定的 effect key。外部效果可能成功但 receipt 尚未落库时按 `effect_unknown` 处理，未经对账不得重放，也不得靠重新授权更换 key。提交后的真实效果继续产生逐动作 receipt 和后置验证证据，不能用授权本身冒充执行成功。

若任务必须先产生不可逆效果才能继续，自治阶段先完成所有安全准备并在该交付边界结束；真人授权提交后，控制内核依据 receipt 启动同一任务的受控后续验证阶段。策略明确禁止或无法安全暂存的步骤直接形成聚合 `blocked` 结果，不循环追问，也不以降低沙箱或扩大宿主权限的方式继续。

替代方案包括 Claude Code 式逐命令确认和 WorkBuddy 式永久 Full Access。前者把策略求解责任转嫁给普通用户并破坏长任务自治，后者把主体、对象、影响、有效期和计划绑定折叠成不可审计的总开关，均否决。

本 ADR 确定目标交互与授权语义，不授权历史 `safe_auto` 绕过 ADR-0047 所承接的确定性校验、主体/对象授权、不可变来源、幂等恢复和真人签发限制。放宽旧实现的单 Agent、无附件、无工具边界前，必须先实现 CanonicalTaskGraph、SessionExecutionGrant、ExecutionBroker、可强杀沙箱、不可变 Delivery Bundle 与相应 invalid-first 测试，并为实际 Schema/API/状态机变化另行取得实施授权。
