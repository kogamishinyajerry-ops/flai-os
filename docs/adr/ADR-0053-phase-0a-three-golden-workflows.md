# ADR-0053：Phase 0A 三条黄金工作流

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0005、ADR-0015、ADR-0016、ADR-0027、ADR-0050、ADR-0051、ADR-0052

Phase 0A 面向 5–8 名具名技术验收人员，只把三类完整用户结果作为对外黄金工作流：智能办公助手、CFD 工程助手和会议行动助手。黄金工作流是用户从单一 Composer 提交目标后，由控制内核自动编排有界技能或 Agent 完成并形成 Delivery Bundle 的端到端任务，不等同于一个大而全 Agent，也不以展示 Agent 数量为目标。

智能办公助手作为长期能力族负责高频个人内容生产，可逐步承接报告润色、文档总结、Excel 分析、PPT 材料、规章快查、邮件草拟和基础纪要整理；底层能力必须按文件类型、知识范围和外部影响拆成最小技能。**本次 Phase 0A 只开放 ADR-0054 的 DOCX 技术报告润色 tracer**；其余能力保持后续候选。首切片只修改隔离副本，不能用“办公助手”名义取得永久 Full Access、直接控制 Office GUI 或外发内容。

CFD 工程助手作为长期能力族面向已有算例与结果，可逐步覆盖设置检查、隔离副本优化、后处理、绘图和报告。**本次 Phase 0A 只开放 ADR-0055 的 OpenFOAM 算例只读体检 tracer**；不修改原件或副本，不启动 solver、`checkMesh`、脚本或后处理。后续能力必须另行定义并验证，模型建议或报告措辞始终不能冒充工程判定。

会议行动助手作为长期能力族与普通纪要润色分开：它可逐步覆盖正式会议记录草稿、责任事项接收、成果提交和验收跟踪。**本次 Phase 0A 只开放 ADR-0056 的会后纪要与行动项整理 tracer**；只生成带来源的 synthetic 草稿和聚合例外，不创建真实责任事项、不通知、不跟踪、不签发正式记录。AI 在任何阶段都不代替验收人关闭责任事项。

性能盘批处理继续作为已有工程工具链和文件产物的内部技术验收样板，并可在接入真实计算、完成工程验证后进入 Phase 0B 专业能力；它不占据 Phase 0A 三条对外类型槽。FEA、控制逻辑、FTA、P-ACE、Agent 市场、邮件自动发送和全自主 CAE 等能力本阶段冻结但不永久否决。

本 ADR 只锁定三条工作流的产品边界，不决定开发顺序，也不授权现有 L0 Agent 以生产能力名义开放。每条工作流仍需选择一个最小 tracer bullet、定义 invalid-first 验收并通过相同的授权、Sandbox、证据和交付门。
