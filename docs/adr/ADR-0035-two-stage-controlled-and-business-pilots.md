# ADR-0035：受控验收与业务试点分两级推进

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0005、ADR-0007、ADR-0029、ADR-0033、ADR-0034

FLAi-OS 首轮不直接面向 20–30 名业务用户开展所谓生产试点。Phase 0A 仅由 5–8 名具名技术验收人员在 macOS 首发环境和 canonical/synthetic 数据上运行少量黄金任务，验证不中断自治会话、沙箱与强杀、并发与恢复、审计证据、真实状态和末端交付授权。该阶段的通过只证明平台机制在限定场景成立，不证明工程结果有效、真实业务价值成立或平台生产就绪。

只有 Phase 0A 的机械门禁通过，且至少一条工作流已经接入真实工具与真实数据、完成安全与准确性验收后，才进入 Phase 0B：向 20–30 名具名业务用户开放限范围业务试点。业务试点仍按 Agent、项目、数据域和能力清单逐项开放，未列入范围的能力保持不可见或明确未开放，不能以“平台已有人使用”外推为全面上线。

直接让 20–30 人使用当前 L0 Mock、固定 canonical CFD 和合成知识语料虽然能快速获得界面反馈，但会把演示能力误传为工程能力，并使安全缺口与产品体验问题同时暴露，故否决。等待所有领域能力完整后再试点同样否决，因为它延迟了对控制内核和自治交互的真实验证。

本 ADR 只确定试点人群与成熟度语义，不批准任何当前 Agent 进入 Phase 0A/0B，也不授权处理真实敏感数据。每条黄金任务、验收命令和扩大人群条件仍需独立明确。
