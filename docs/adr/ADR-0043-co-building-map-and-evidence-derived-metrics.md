# ADR-0043：建立 FLAi 共建地图与证据化运营指标

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0029、ADR-0036、ADR-0037、ADR-0041、ADR-0042

FLAi-OS 为全体参与者提供“FLAi 共建地图”，让团队看见平台当前版本、已具备和正在建设的能力、下一阶段目标、真实使用、反馈与价值证据。它是面向全员的只读共建进展面，不替代工程智能体工作台，不拥有任务、评测、版本或授权的独立事实源，也不把后期智能化指挥中心提前做成普通用户首页。

共建地图采用“战略目标 → 平台地基 → 黄金工作流 → 能力发布包 → 证据”的结构。战略目标、能力关系、里程碑定义、优先顺序和路线图版本由具名人员制定并变更留痕；节点状态只能由能力发布、FLAi Bench、人工签发、生产准备或其他明确证据派生，展示层不得手工把节点点绿。没有证据的节点显示计划中、进行中、证据待补、受阻或未知，不使用没有冻结分母和验收条件的“平台完成度 83%”一类数字。

普通用户首页可以展示共建地图摘要、当前版本、本周新解锁能力、下一步目标和近期真实里程碑，并提供进入完整地图的入口。治理与运行角色可以进一步查看每个节点的评测、风险、授权和审计证据；敏感信息继续按分类和角色收容。现有 Today 页面、`GET /api/stats/overview`、任务事件、tool_runs、model_calls、feedback、eval_runs、promotions 和能力发布事实继续作为演进 seam，不建立平行 KPI 或 trace 平台。

运营指标分为当前能力、使用采纳、质量安全、资源消耗和组织价值五类。每个公开指标必须绑定 `definition_version`、`since`、`until`、`sample_count`、事实源、分子分母或等价计算规则，以及 unknown/null/zero 的区分；无法计算时显示“未知”或“尚未建立基线”，不得填 0 或推算成漂亮比例。

当前能力从能力发布包和受验证的 Agent/Tool 清单派生，展示实际版本、已验证范围和明确限制。使用采纳按时间窗口内产生真实 user-origin 任务或等价真实工作行为的认证用户计算，不以注册账号数、页面访问量或 eval 任务冒充活跃；公开视图展示团队聚合、复用人数、任务终态和工作流分布，不建立个人任务量、Token 或生产力排行榜。

质量安全从 FLAi Bench、人工评审、反馈、失败与治理事件派生，评测失败、线上失败、审计违规和人审退修分别呈现，不合并成误导性的单一“质量分”。资源消耗从 model_calls、tool_runs 和任务时间戳等事实源统计 Token、模型调用、时延、并发、资源与稳定性；Token 是资源成本而不是贡献度。只有价格表具有适用模型、币种、有效期和版本时才显示估算成本，否则只报告 Token 和未知成本。

组织价值中的“节省时间”不得由 LLM 自评，也不得用 Agent 运行时长直接推导。平台只有在可比较任务类型存在具名基线方法、基线版本、有效样本量和人工抽样确认时，才报告区间化节时估算及覆盖率，例如“预计节省 42–58 小时，来自 27 个有效样本”；没有基线就明确显示未建立。数据收集应采用试点抽样、周期性轻量回访或已有任务证据，不能在每次 Agent 工作中插入复杂表单。

全员视图只展示适当粒度的团队聚合。个人任务、反馈、节时样本和敏感工作流明细只对本人及授权治理角色可见；小样本可能导致身份反推时必须合并、抑制或脱敏。共建感通过已验证里程碑、版本变化、反馈转化和团队贡献叙事建立，而不是通过个人排行榜或竞争性积分制造。

共建地图的状态、版本和指标全部是既有事实的只读投影。地图可以解释“为什么处于这个状态”，并链接证据；无权直接改变任务、晋级、知识发布、安全授权或 Benchmark 结果。路线图本身的变更必须保留版本、变更人、时间和理由。

本 ADR 决定产品面和指标可信边界，不授权当前混合工作树上的 API、数据库或前端改动。实施前必须固定地图节点与证据引用合同、路线图版本机制、指标定义注册表、隐私聚合规则、节时基线方法、unknown/null/zero 行为，以及至少覆盖 eval-origin 污染、重复事件计数、缺失 Token 冒充 0、无基线节时和手工点绿的 invalid-first fixtures。
