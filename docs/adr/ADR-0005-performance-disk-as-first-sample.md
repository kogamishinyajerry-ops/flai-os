# ADR-0005: 性能盘批量调用 Agent 作为第一业务样板

- 状态：已接受（任务书 §11 定版，2026-07-08）
- 背景：第一个样板决定平台口碑与数据资产起点，必须选「高频、重复、规则明确、
  耗时、有真实用户」的场景。
- 决策：第一样板 = 性能盘批量调用 Agent（工具自动化型）：上传需求表格 → 校验 →
  批量 case → 调性能盘 → 解析 → 汇总 Excel + 简要报告 → 沉淀 samples。
  M3 先做 Mock 工具版验证平台闭环，M4 才接真实性能盘。
- 理由：①业务价值直白（减少人工重复调用）；②LLM/确定性边界清晰（数值全在
  工具，LLM 只做字段映射建议与报告叙事）；③每次调用天然沉淀输入输出样本，
  为后续代理模型/敏感性分析/反向拟合铺数据地基。
- 边界（同 agent.yaml limitations）：不做 APU 全性能分析、不与控制逻辑/FTA
  强制串联、不替代性能专业人员判断、不让 LLM 猜性能盘内部机理。
- 影响与风险：真实性能盘调用形态（命令行/GUI/Excel 宏）未侦察——M4 前必须
  拿到「脱敏样例输入 + 入参清单」两个解锁物；拿不到则 M4 顺延，M3 Mock 版
  照常收口（Mock 如实标注）。
