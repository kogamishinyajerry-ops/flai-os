# ADR-0039：CFD 工程助手首个薄切片采用算例体检

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0025、ADR-0027、ADR-0034、ADR-0037

CFD 工程助手的第一个完整 tracer bullet 是“CFD 算例体检”。用户从单一 Composer 提交已有 OpenFOAM 算例或算例压缩包，并描述任务目标与工况；系统在只读、隔离环境中检查算例完整性、求解器与物理模型、材料与边界条件、网格质量证据、时间步与 Courant 数、收敛控制、离散格式、线性求解设置以及后处理输出配置。

每条发现必须包含检查项、当前设置、判断状态、风险等级、具体证据文件与字段位置、修改建议和无法确认的前提。系统不得只给“总体合理”等无证据结论；缺少网格质量日志、工况、物性或其他必要事实时明确标记未知，不让模型补造。输出是辅助体检报告和结构化 findings，不构成工程校核或求解有效性判定。

首版全程只读，不修改原算例或副本、不启动求解、不自动选择所谓最佳模型或参数。后续只有在本薄切片通过验收后，才分别考虑隔离副本上的受控配置修改，以及对已有求解结果的后处理和报告；二者不得被打包成一次范围扩张。

现有固定圆柱绕流 Re=100 的 `cfd_solve_agent` 继续作为内部 Runtime/监控技术样板，不作为首发产品能力。选择只读算例体检，是为了先以可追溯建议获得工程师信任，同时验证大型目录输入、配置解析、证据锚定、未知态和 Delivery Bundle，而不提前引入自主求解的资源与安全风险。

本 ADR 决定产品薄切片，不授权当前混合工作树上的实现。正式开发前仍需确定首个受支持的 OpenFOAM 版本/求解器、算例包大小与文件类型预算、恶意压缩包防护、字段解析器、确定性检查规则和 golden fixtures。
