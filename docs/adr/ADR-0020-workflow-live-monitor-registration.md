## 背景与定位重述（owner 2026-07-12）

原议题是「mac 上的仿真监控模块要不要注册接入平台」。owner 重述后的正确定位：
**注册对象不是监控实例，而是一套“把任意工作流变成可实时追踪窗口”的方法**——
接入规范已成文、已在三个异构求解域验证、内网换任何引擎只改 adapter 不改方法；
且该方法本身可由 agent 起草新接入（「产生工作流的工作流」）。

原定位的三个注册阻塞在新定位下部分解开：多用户可见性争议集中在**转录
surface**（操作员 Agent 会话），而**仿真 surface**（求解器真源）可先行注册。

## 决策

1. **以「标准 + 生成器 + 窗口」三件套注册**，而非注册某台机器的监控页：
   - 标准 = docs/09（接入契约、双层诚实模型、tamper 实证门、接缝契约）；
   - 生成器 = `monitor_adapter_gen` agent（起草新工作流的 adapter，走 L0→L1
     治理轨道，draft 永不自动生效）；
   - 窗口 = 已交付的浮窗/完整面板（消费接缝契约的通用 UI，SSOT 在监控节点）。
2. **智能展示红线入标准**：Agent 可智能化「展示什么」（选择权，叙事层标注），
   绝不智能化「数据本身」（生成/插值/美化零容忍）。监控线永远是只读观察者，
   不兼任执行者（观察者兼执行 = 自己给自己打分，验证价值归零）。
3. **分相注册**：
   - **R1 仿真 surface 平台可发现**——前置：M11 鉴权落地 → verify_all 全量
     复跑 + 探针改真登录 → StatusDock 发现入口 + per-task run_ref 落库
     （即监控线决策书 Next-2 转正批，顺序不跳队）。
   - **R2 生成器 agent 注册**——按 02 Agent 包标准立包，07 评测标准固化
     case，M10 晋升门放行。
   - **R3 转录 surface 入平台发现面**——**唯一前置 = owner 裁决多用户可见性
     授权模型**（谁能看、看谁的会话、EAR 语境默认拒绝）；裁决前保持操作员
     本机档位（回环 + pin 锁定 + fail-closed 启动门）。

## 后果与风险

- 好处：注册物与平台定位对齐（运行底座收方法性资产，不收机器绑定实例）；
  最敏感面（转录）与最有价值面（仿真真源直播）解耦，前者不再阻塞后者。
- 风险①：生成器 agent 起草的 adapter 若跳过 tamper 实证直接用 = 把假绿
  批量化。对策：标准 §4 把实证定为硬门，draft 不实证不注册（fail-closed）。
- 风险②：监控节点（mac）仍是单点，hub 侧无鉴权是已知边界——R1 注册范围
  声明「监控数据面向内网只读」，最小访问控制挂 M4 内网前置清单一并裁。
- 残余：转录 surface 可见性模型属 owner 决策，本 ADR 不代拍。
