# ADR-0038：智能办公助手首个薄切片采用技术报告润色

- 状态：产品方向已接受（委托人在本次设计会话中确认，2026-07-23；不构成组织签发、试点或上线授权）
- 关联：ADR-0034、ADR-0036、ADR-0037

智能办公助手的第一个完整 tracer bullet 是“技术报告润色与规范化”。用户从单一 Composer 上传一份 DOCX 并描述目标，系统自动解析、规划和处理，在隔离工作区生成修改副本，最后以 Delivery Bundle 交付修改后的 DOCX、修改摘要、重要差异、无法确认或可能改变原意的问题，以及对应文件和执行证据。

首版只支持 DOCX，不同时实现 PDF 编辑、Excel 分析、PPT 生成、邮件连接器或知识库问答，也不通过 GUI 自动控制 Microsoft Office。原文件不得覆盖；数字、单位、公式、表格和图片不得被模型静默改变；系统不得补造事实、出处或工程结论。若某项语言修改可能改变技术含义，保留原文并列入待确认问题，而不是中途逐段追问。

选择该薄切片而不是先做 PPT、Excel 或邮件，是因为它高频、结果直观，又能在较小范围内同时验证附件授权、OOXML 解析与生成、模型调用、隔离副本、差异展示、证据链和末端交付。后续 Office 能力只有在这条闭环通过用户验收和安全门后才依次加入。

本 ADR 决定产品薄切片，不授权当前混合工作树上的实现。正式开发必须从干净基线开始，并先明确 DOCX 保真判据、恶意文档处理、大小/复杂度预算、不可变输入快照和 invalid-first 验收。
