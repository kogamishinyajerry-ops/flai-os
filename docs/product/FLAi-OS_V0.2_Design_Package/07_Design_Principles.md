# 07｜设计原则

## 1. 状态标签

| 标签 | 含义 |
|---|---|
| `IMPLEMENTED-VERIFIED` | 当前精确范围、版本与环境有可复跑机械证据，绑定命令、结果引用和日期；不等于生产就绪 |
| `IMPLEMENTED-PARTIAL` | 已有可复用基础，尚未满足本原则的完整合同 |
| `ACCEPTED-NOT-IMPLEMENTED` | 已被 ADR 接受，尚未完成实现与验证 |
| `DECLARED-NOT-VERIFIED` | 候选做法或外部声明，不能当作本项目事实 |
| `OUT-OF-SCOPE` | 当前阶段明确冻结 |

所有原型、设计评审和实现计划都必须逐条说明状态。视觉完成度不能把 `ACCEPTED-NOT-IMPLEMENTED` 变成“已支持”。

## 2. 产品北极星

`ACCEPTED-NOT-IMPLEMENTED`

FLAi-OS 应让中国企业用户获得 WorkBuddy 式的低门槛：用“任务、项目、资料、产物”等熟悉名词开始工作；同时获得 Claude/Codex 式的高透明度：清楚看见系统正在做什么、依据是什么、产物如何变化。安全复杂度由平台实现承担，不转嫁成普通用户的长表单和连续审批。

设计质量的判断不是“像哪款产品”，而是同时满足：

- 用户能无培训地发起真实工作；
- Agent 能在受控范围内连续完成工作；
- 任何状态、结论、产物和交付都能回到真实证据；
- 人类只在真正需要权威的末端做清晰决定；
- 失败、未知和限制比“看起来顺利”更诚实。

## 3. 十五条不可稀释的原则

### 3.1 目标先于 Agent

`ACCEPTED-NOT-IMPLEMENTED`

当前部署域的 FLAi 工作收件箱把单一 Composer 作为首要动作，工程工作台也用同一目标语义进入执行；外网研发域可由飞书承载入口，内网生产域只能由自托管 `FLAiWorkspace` 承载。首问“你要完成什么”，不是“你要创建几个 Agent”。Agent、Skill、Tool 和模型属于平台编排实现；只有当调整能力确实影响任务结果时，才在提交前渐进披露。

反模式：Agent 市场成为首页、先让用户选技术栈、把工作流配置表当成新手入口。

### 3.2 一次提交，连续工作

`ACCEPTED-NOT-IMPLEMENTED`

用户提交目标后进入自治会话。Agent 在策略允许的可逆范围内连续规划、执行、验证、恢复，不要求用户把系统已推导出的内容重新填入表单，也不逐命令、逐工具、逐文件确认。

反模式：计划生成后要求用户补责任人和每一步参数；使用泛化审批弹窗模拟安全；用永久 Full Access 换取流畅。

### 3.3 状态来找人

`IMPLEMENTED-PARTIAL`

状态坞、对话内活任务条、速览和深链已提供基础。目标态要求排队、执行、验证、恢复、待交付、受阻、失败和未知均来自权威事实，并在相关上下文中主动出现。用户不需要记住“去哪看任务”。

反模式：只有“正在思考”；让用户去日志页猜进度；用无法证明的百分比和循环动画制造活跃感。

### 3.4 过程可检查，但不泄露思维链

`ACCEPTED-NOT-IMPLEMENTED`

时间线展示结构化计划摘要、工具动作、策略结果、输入快照、验证、重试和证据引用，不展示或声称保存模型完整内部推理。专业用户可展开脱敏细节，普通用户默认看到能判断工作状态的最小信息。

反模式：把原始 JSON 当透明度；把自然语言“我正在……”当执行证据；默认暴露环境变量和 secret。

### 3.5 产物与证据必须同屏可达

`IMPLEMENTED-PARTIAL`

产物不是聊天附件尾注，证据也不是另一个后台。每个可交付产物必须能回到输入快照、关键差异、来源锚点、tool run、验证状态和限制；右侧检查器允许用户在不离开会话的情况下预览和对比。

反模式：只有最终文件，没有差异和来源；`completed` 自动等于可信；草稿自动进入正式资产。

### 3.6 人只在权威改变处签发

`ACCEPTED-NOT-IMPLEMENTED`

正式工程资产、外部系统或组织事实的不可逆改变被编译进不可变 Delivery Bundle。具名真人在末端对精确版本一次决定；授权、真实执行和后置验证分别有证据。人签不等于执行成功，评测通过也不等于人签。

反模式：AI 自批；中途泛化逐动作审批；把“审核通过”涂绿并当作外部动作已完成。

### 3.7 证据不足就说无法确认

`IMPLEMENTED-PARTIAL`

缺来源、冲突、不可解析、观测中断和样本不足都必须有一等 `未知` 语义。未知不能转换成 0、低风险、通过或“总体合理”。三条黄金工作流都要把无法确认项集中到末端，不在过程中循环追问。

反模式：模型补全边界条件；把缺失 Token 记为 0；没有节时基线仍显示节省百分比。

### 3.8 安全是后台合同，不是前台摩擦

`ACCEPTED-NOT-IMPLEMENTED`

身份、作用域、数据分级、会话期限、网络、工具能力、并发预算、停止和审计由控制内核判定。普通用户看到一句能理解的范围摘要和必要限制，不负责填写策略语言。禁止或无法安全暂存的动作明确受阻并 fail-closed。

反模式：把沙箱当文件夹命名；让用户凭感觉批准 shell 命令；错误后建议扩大宿主权限继续。

### 3.9 一个事实，多种角色投影

`ACCEPTED-NOT-IMPLEMENTED`

当前部署域的工作收件箱、工程工作台、治理与运行中心、FLAi 共建地图和智能化指挥中心读取同一组联邦权威事实。外网研发域由 GitHub、飞书和 `secrets-stackdocker` 分别拥有各自事实；内网生产域由 Internal Forge/Registry、FLAi Control Kernel、Knowledge Authority、Audit/WORM 和 Internal Secret Owner 分别拥有各自事实。两域不共享在线状态机、用户库、密钥值或协作表副本。

反模式：管理大屏手工录入进度；治理中心自行改完成状态；全局管理员默认拥有所有专业签发权。

### 3.10 共建要低门槛，采纳要有责任

`ACCEPTED-NOT-IMPLEMENTED`

任何认证试点用户都能用一句自然语言提出需求，并可关联当前工作证据。AI 只做预处理草稿；需求策展、领域与安全评审、路线图签发和交付验收职责分离。合并、暂缓和不采纳都保留来源并回告。

反模式：长 PRD 表单；点赞自动晋级；AI 自动建 Issue；代码合并后宣布用户问题已解决。

### 3.11 中国用户优先，工程语义不降级

`ACCEPTED-NOT-IMPLEMENTED`

界面以简洁中文为主，使用“任务、资料、产物、依据、待确认”等工作语言；专业缩写首次出现时给出中文解释。支持中文姓名、中文文件名、长单位、全角标点和本地 24 小时时间表达。面向 macOS 桌面优先打磨，但交互合同不依赖终端、英文命令或开发者知识。

反模式：把 `queued`、`tool_run`、`MCP` 直接呈给普通用户；用“低代码编排”要求业务用户理解技术图；把中文路径异常当边缘情况。

### 3.12 克制、可访问、可撤销

`IMPLEMENTED-PARTIAL`

每屏一个主动作，其他信息渐进披露；动效只解释真实变化。所有关键状态使用文字、图标、形状和可访问名称，不仅靠颜色。键盘、清晰焦点、200% 缩放、减少动态效果和屏幕阅读顺序是验收条件。可逆动作优先，停止、返回和关闭不会丢证据。

反模式：高密度控制台塞进聊天；颜色是唯一状态信号；自动轮播状态；关闭面板即丢上下文。

### 3.13 一个日常中枢，不是一个总数据库

`ACCEPTED-NOT-IMPLEMENTED`

每个网络域只有一个日常入口：外网研发协作从飞书 FLAi 研发空间发现、编排和回告；内网生产协作从自托管 `FLAiWorkspace` 发现、编排和回告。GitHub 与 Internal Forge 的原生代码操作、工程工作台和治理专业 Surface 都需要重新鉴权，但不另建同域组织首页。协作 Surface 只拥有原生协作事实、权限过滤投影和治理意图，不能通过表格字段、卡片点击或缓存接管代码、FLAi、Knowledge、Audit 或 Secret owner。跨域只允许经 `AirGapExchange` 传递签名、内容寻址、可审查的离线包。

反模式：为“统一”把所有状态双写到协作表；让最后写入者获胜；让外网飞书成为内网运行依赖；另保留一套同域日常管理后台。

### 3.14 点击不是生效，回执才是

`ACCEPTED-NOT-IMPLEMENTED`

所有会创建或改变跨 owner 正式事实、受控投影或外部 effect 的 Workspace 动作都是版本化 typed
intent；协作系统自有群聊、评论、Wiki 与协作草稿保持 surface-native，只有提交为
DemandSignal、正式记录或其他 owner 事实时才进入当前域的 Hub。外网研发 Hub 不得把 typed intent
定向到内网生产 owner；跨域输入必须先成为通过 `AirGapExchange` 准入的离线包。高影响动作先冻结 PreparedCommand 并展示精确
ReviewChallengeV1，提交时使用新鲜身份重新检查 payload/target digest、ActorBinding、认证
assurance、职责、ACL、classification、epoch 和职责分离；只有有效 OwnerCommitReceiptV1
才显示生效。EffectUnknownV1 必须对账，不能换幂等键重放。

反模式：卡片显示“成功”却没有 owner receipt；用 HTTP 2xx、消息送达、改单元格或离线包“已复制”代替签发。

### 3.15 密钥不进入协作面，安全止损不依赖协作面

`ACCEPTED-NOT-IMPLEMENTED`

外网研发域的运行时 App/Connector Secret value 由 `secrets-stackdocker` 管理；内网生产域使用独立部署、独立信任根、独立命名空间和独立值的 Internal Secret Owner。Hub 与普通 Connector 只持有当前域的 opaque `SecretRef`；解析失败、撤销或版本 unknown 时 fail-closed，不回退历史 `.env`、硬编码或另一网络域。人的安全硬件身份与 Safety receipt-signing key 由独立 Safety Identity / PKI / HSM owner 持有。当前域 Workspace 不可用时，新的正常治理暂停，但密封、强审计、只减权的 kill/revoke/isolate/credential invalidation 通道仍可用。

反模式：把 key 放入卡片、协作表、离线包、日志或 Agent prompt；Workspace 故障时无法强停；把 break-glass 变成备用发布后台；复制外网密钥进入内网。

## 4. 信任视觉语法

`IMPLEMENTED-PARTIAL`

当前设计 token 与核心视图已有五槽信任色锁实现与历史视觉证据，但本设计周期没有对 clean release 做完整视觉/无障碍验收；V0.2 必须继承，不得为新页面另开语义。

| 颜色槽 | 唯一语义 | 必须同时使用的非颜色信号 |
|---|---|---|
| clay | 工作、进行、选择 | 动词状态、进度阶段、可访问名称 |
| 绿 | 已由可核证据确认的 REAL 数据或结果 | “已验证”文字、证据入口 |
| teal | 具名真人签发时刻 | 签发人、时间、精确版本 |
| 红 | 真实失败或明确驳回 | 失败原因、影响范围、恢复路径 |
| amber | 未核、降级、等待人处理或证据未知 | “待确认／未知／降级”文字及原因 |
| 中性墨色 | 普通完成、取消、历史、无动作状态 | 完整状态文字 |

硬约束：`completed` 不自动给绿；按钮成功不借用绿；人签前不预支 teal；失败不做庆祝动效；分类色不得撞信任色。

## 5. 中文内容原则

`ACCEPTED-NOT-IMPLEMENTED`

### 5.1 状态用“事实 + 影响 + 下一步”

好的状态文案：

> 网格质量日志缺失，当前无法确认非正交性风险。其余 18 项检查继续完成；缺失项已列入交付例外。

不好的状态文案：

> 发生未知错误。请重试。

状态文案不得掩盖主体：区分“系统未观测到”“资料没有给出”“策略禁止”“真实执行失败”和“人已驳回”。

### 5.2 不把可信度写成伪精确百分比

需要人判断时展示来源覆盖、冲突和缺失项，不展示无法校准的“可信度 92%”。指标百分比必须有分子、分母、窗口、样本和定义版本。

### 5.3 专业事实与建议分栏

CFD 当前设置、文件字段和确定性检查结果属于事实；风险解释和修改方案属于建议；缺少工况或物性属于未知。三者不能混成一段“综合评价”。

### 5.4 术语保持单一

全产品沿用 [CONTEXT.md](../../../CONTEXT.md) 的术语。禁止同一对象在不同页面被称为“交付包／审批单／任务结果”三种名称，也禁止把会议草稿称为正式纪要。

## 6. 无障碍与包容性验收底线

`ACCEPTED-NOT-IMPLEMENTED`

1. 所有核心流程可仅用键盘完成；焦点顺序与视觉顺序一致，弹层关闭后焦点回到触发点。
2. 焦点环始终可见；错误、未知、工作中和人签状态不只靠颜色或动画表达。
3. 使用语义标题、列表、表格和状态区域；动态状态通过克制的 live region 通知，不朗读每条日志洪流。
4. 200% 缩放和窄窗口下不遮挡 Composer、停止、产物预览与末端交付动作。
5. `prefers-reduced-motion` 下移位、缩放和粒子动效关闭，信息和操作保持完整。
6. 文件、图表、差异和来源锚点有文本替代；仅图片呈现的 CFD 结论不合格。
7. 中文输入法组合期间不得误提交；快捷键必须有可发现的按钮等价路径。
8. 错误提示与字段或动作建立程序化关联，不能只弹三秒 Toast 后消失。
9. 重要倒计时和过期不依赖颜色闪烁；用户可暂停非必要动态内容。
10. macOS 桌面优先不等于鼠标优先，也不等于忽略低视力、减少动态效果和屏幕阅读用户。

## 7. 深 Module 设计纪律

`ACCEPTED-NOT-IMPLEMENTED`

产品简单不能靠把复杂度散落到每个页面。设计与实现应把复杂行为收进深 Module：

- **Composer Module** 的 Interface 只要求目标、附件和可选上下文；能力解析、输入快照、策略摘要与任务图在实现内部完成，以 Depth 换取用户 Leverage。
- **会话时间线 Module** 的 Interface 接收权威事件和访问主体；中文映射、折叠、脱敏、未知和恢复逻辑集中，保持 Locality。
- **产物与证据 Module** 的 Interface 返回可检查对象和合法动作；DOCX、文本、CFD 文件等 Adapter 位于真实格式 Seam 后方。
- **Delivery Bundle Module** 的 Interface 只暴露精确版本、影响摘要、证据、残余风险和合法决定；CAS、策略重检、过期及 receipt 属于实现。
- **角色投影 Module** 的 Interface 依据主体、职责和作用域返回可见信息与动作；页面不得复制权限 if/else。

删除测试：若删除一个 Module 后，权限、状态或证据复杂度会重新散到多个页面，它有足够 Depth；若删除后只少一层转发，则该 Module 过浅。只有存在两个真实 Adapter 时才建立 Seam，不为假想未来堆抽象。

## 8. 三条黄金工作流的一致设计合同

`ACCEPTED-NOT-IMPLEMENTED`

| 工作流 | 用户只需提供 | 系统连续完成 | 末端必须看见 |
|---|---|---|---|
| 技术报告润色与规范化 | DOCX + 一句话目标 | 解析、保护项识别、润色副本、差异、验证 | 修改副本、重要差异、未确认问题、原件未覆盖证据 |
| CFD 算例体检 | OpenFOAM 算例 + 任务目标／工况 | 只读解析、确定性检查、证据锚定、风险建议 | findings、文件字段证据、未知前提、未启动求解声明 |
| 会后纪要与行动项整理 | 会后文本材料 + 会议上下文 | 来源解析、结构化提取、锚定、例外聚合 | 工作包、决策/共识/未决、责任五字段、签发精确版本 |

三条工作流都不在中途要求长表单；都将未知与例外集中到末端；都不让 AI 签发工程或组织事实。

## 9. 设计评审问题

每次原型或实现评审必须回答：

1. 用户能否不理解 Agent 架构就开始真实工作？
2. 是否把系统能推导的信息重新要求用户填写？
3. 每个“正在做／已完成／已验证／已签发”能否回到不同的真实证据？
4. 网络中断、来源缺失、状态不可解析和策略拒绝时，界面是否如实保留上下文？
5. 是否出现了不必要的中途人类决定？若出现，它改变的究竟是什么权威事实？
6. 普通用户与治理角色是否读取同一对象，而不是两份状态？
7. 是否用颜色、动效、综合分或漂亮数字夸大了证据？
8. 中文名称、键盘、缩放、减少动态效果和屏幕阅读路径是否通过验证？
9. 新设计是增加了 Module 的 Depth，还是把实现复杂度泄露到 Interface？
10. 关闭或撤回动作后，证据是否仍完整并可追溯？
11. 当前域 Workspace 中的字段究竟是 collaboration input、draft、governed command input、authoritative projection 还是 derived metric？
12. 任何治理“已生效”是否有匹配 owner/version/digest 的 OwnerCommitReceiptV1，而非卡片点击或 HTTP 2xx？
13. 当前域 Workspace 或 Secret Owner 不可达时，系统是否 fail-closed 且仍能完成必要止损？
14. 设计是否错误地让外网飞书、GitHub、模型服务或密钥成为内网在线依赖？

## 10. 非目标

`OUT-OF-SCOPE`

- 不照抄 WorkBuddy、Claude 或 Codex 的品牌、图标、布局和动效。
- 不用“极简”删除安全范围、来源、限制与错误信息。
- 不用“企业级”增加无意义审批、字段和管理层级。
- 不以视觉设计稿证明 Runtime、Sandbox、授权、评测或审计已经实现。
- 不把飞书、自托管协作表或独立管理页建成第二控制面或第二事实源。
- 不建设飞书到内网的在线同步、共享身份、共享密钥或远程控制通道。
- 不在 V0.2 设计包中承诺 Windows 适配、实时会议、全自主 CFD 或自动外发。
