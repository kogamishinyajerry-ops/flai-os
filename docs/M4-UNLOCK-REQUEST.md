# M4 解锁物与现场确认索取单（一页纸，可直接转发）

> 背景：FLAi-OS 已用明确标注的确定性 mock 验证性能盘任务调用链；真实适配器、
> 目标机环境、组织评审关系与模型独立性仍待现场证据。我们这次既索取 adapter
> 所需结构，也采集后续判断资产、课题延续与评审政策的真实前置，不把演示闭环外推为
> 已具备真实业务能力。

## 性能盘 adapter 需要什么

1. **一份脱敏样例输入**：真实性能盘一次典型计算所需的完整输入（Excel/文本/
   命令行参数均可），数值可脱敏替换，但**格式、字段名、单位、文件结构必须
   保真**——适配器按它写解析。
2. **入参清单**：性能盘可调输入参数的完整列表（参数名/类型/单位/合法范围/
   默认值），以及输出结果的字段说明。有现成文档复印即可，不必新写。

## 另请协调三类现场确认

3. **真实评审关系**：请业务负责人用一条真实流程说明「谁创建、谁初审、谁最终签发、
   谁批准发布」，以及各主体可处理的类别。可在受控记录中用人员映射编号，但须由具名
   owner 可回查；平台不会凭 username 猜角色。
4. **模型家族清单**：请模型服务方说明内网可用模型的提供方/基础家族/版本，重点确认
   是否存在 GLM 之外的第二家族，并允许用真实端点做最小探针。只有同源模型也是有效
   结论，我们会如实提高确定性核验权重与人工抽检地板。
5. **永久人工签发地板**：请数据/出口管制责任人确认 `sensitive` 与 EAR 相邻类别的
   实际映射和 policy owner。这些类别在平台中永久保持 **100% 具名人工签发**，不得
   因模型成熟度或一致率降为免人签。

## 顺带想确认的（当面 10 分钟）

- 性能盘的调用形态：命令行？COM/DLL？Excel 宏？人工操作界面？
  （决定适配器形态，`docs/M4_intranet_day1_recon_checklist.md` ④组）
- 一次典型计算的耗时量级（秒/分钟/小时——决定平台侧超时与队列策略）；
- 内网机器的 Python 环境与安装限制（有无内部 pip 镜像）；
- 上述评审关系是否存在自审/代理签发/类别例外；若尚无制度，请直接记「未定义」。

## 脱敏要求（我们主动承诺）

- 样例数值可全部替换为虚构值，我们只需要**结构**；
- 平台内所有涉及该工具的样本/产物将带数据分级标记，管控见平台治理文档；
- 出口管制敏感型号词一律不进平台仓库与界面（既有红线纪律）。
- 人员关系可用受控映射编号，公开仓库不记录不必要的姓名/工号；原始证据按现场制度保管。

## 为什么现在要

平台的可信治理链已经建成，但真实判断、真实课题与真实使用结果尚未形成复利。
这些材料越早到位，M4 开闸后的第一天就能开始如实积累；在它们到位前，平台不会
提前实现课题级跨会话依赖或评审放权，也不会把 mock/合成证据冒充真实业务信号。
