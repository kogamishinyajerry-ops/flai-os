## 一、触发与目标

Owner 需求：「继续回到 UI/UX 设计，仍以 Claude 和 Codex 的设计哲学为标杆，让产品**更加简单好用**」。
四个摩擦点全中：概念/入口太多 · 单屏太满太吵 · 具体流程有摩擦 · 第一次上手不明确。

**根因（实测）**：产品经多批 additive UI 长大，复杂度整体累积。Claude/Codex 对「什么都重」的答案是
**激进减法**，而非再加一个功能。

**目标**：把重量削到克制，同一时刻只让用户看见「此刻要做的那一件事」；功能全在，按需长出。

## 二、诊断（grounded 密度实测）

`grep` 全前端 8366 LOC / 18 文件。壳与空状态已很 Claude（App.vue 侧栏=品牌+新对话+2 项导航+
历史+身份+页脚；GuidePage 空态=衬线问候+四意图卡）。**重量集中在两处**：

| 位置 | 实测 | 性质 |
|---|---|---|
| 对话里的方案卡（GuidePage orchestrate plan-card） | 单张 Agent 卡 ~11 元素 × N，一条消息 ≈40 控件（GuidePage 共 85 控件 / 1627 LOC） | **星号密度源**：把控制面板塞进一条对话消息 |
| 任务详情整页（TaskDetail） | 87 控件 / 918 LOC，你要「跳过去」看 | 二级整页过载 |
| 任务台 route（TaskConsole）≈ 状态中心（StatusCenter） | 两份高度重叠的总览 | **双 Surface 心智税** |

单张 Agent 卡的 11 元素：accent 条 · step 圆 · 名 · 分类 pill · maturity/status 文本 ·
督战状态灯 · 产物锚点行 · rationale · 分工 role · 草案 toggle+JSON · 「去创建此任务」CTA。

## 三、定位：这是 Phase 3，不是另起炉灶

本方案是 UI-PARADIGM 七祈使句**推到逻辑尽头**，而非新范式：

- 祈使句 2「状态来找人」+ 5「页面降级为深链」→ **任务台不再需要占一级导航**，因为状态中心抽屉
  已经就是「总览来找你」。祈使句 5 明定「路由全部保留（可分享/可刷新/可回退）」——故**删的是
  导航入口，不是路由**。
- 祈使句 3「渐进披露四级」+ 4「签发内联」→ 任务速览（peek）+ 内联签发**基建 Phase 1 已交付**；
  Phase 3 只是把「看任务的默认路径」从整页改成速览。
- 祈使句 1「对话是主轴 / 方案卡内联督战」→ 对话主轴变重了；Phase 3 给方案卡做减法，但
  **督战状态语义（imperative 1 承重）一个不减**，只削视觉重量。

## 四、五个减法动作

### 动作 1 — 方案卡：控制面板 → 克制的答案（纯前端）
- 单张 Agent 卡 **11 元素 → 一行**：状态点 + Agent 名 + 一句分工 + 状态词（工作中/待召集/待签…）。
- rationale / 草案 JSON / 剔除字段 / maturity / 分类 pill → 收进**一个「展开」披露**。
- plan-level 保留：**一句引导（含目标+Agent 数）+ 一组 Agent + 一个主动作**（进入协作工作台）。
  analysis / workflow / dropped/capped alerts / plan-note 折叠进披露或收成一句。
- **保留不动**：督战状态点（点击开速览，imperative 1）、产物锚点语义（completed 有产物 → 速览）、
  「想调整？直接告诉导引」逃逸口。削的是**视觉密度**，不是**能力与督战语义**。

### 动作 2 — 任务台 route → 状态中心抽屉（IA 改动）
- App.vue `NAV` 从 `["对话","任务台"]` → **`["对话"]`**（对话成唯一一级入口）。
- 任务总览 + 待签队列并入已有 StatusCenter 抽屉（inbox 视图已含三分组），从状态坞唤出。
- `/tasks`、`/tasks/:id`、`/workbench/*` 路由**全保留**（祈使句 5）；StatusCenter inbox 底部加
  「查看全部任务 →」深链到 `/tasks` 整页（治理场景的全量总览仍可达，只是移出主导航）。
- 直接消掉「入口多 + 双 Surface 心智税」两痛。

### 动作 3 — 任务详情：速览优先，整页降为深链（IA 改动）
- 看任务的**默认路径 = 内联速览面板**（StatusCenter peek，要点 + 产物 + 内联签发，Phase 1 已交）。
- 对话方案卡督战点 / 产物锚 / 状态坞条目点击 → 一律开速览（现状即如此，本动作确保**无一路径**
  把默认点击甩去整页）。
- `/tasks/:id` 整页留作「查看完整页 →」深链（速览面板底部按钮，现已有）。整页 87 控件在**深链态**
  下做二次密度清理（次要区块折叠），非本批阻塞。

### 动作 4 — composer 与全局密度纪律（纯前端）
- composer 已较干净：Agent 选择器 popover 瘦身（保留诚实前置 maturity/limitations）；
  提示句「导引不会替你创建或签发…」**字面保留**（m6 e2e 锚），快捷键仍 hover/聚焦才显。
- 跨屏原则：**每屏一个主动作**，其余进渐进披露或降为安静文本；留白 ≥ 控件密度。

### 动作 5 — 焊死不动的线（红线，见 §六）
信任色锁 / 诚实地板 / 人是唯一发起者 —— 一个都不减。简化只动**密度与层级**，不动**信任语义**。

## 五、落地批次 + 验收 + e2e 消费者清单（safe-refactor 枚举）

小步 · 可逆 · 每批独立验收 · 每批 e2e 契约与实现**原子同批**更新（祈使句红线：e2e 不裸奔）。

### 批 1 — 方案卡减重（动作 1+4 残项）· 低风险
- **验收**：orchestrate 方案卡单卡视觉 ≤ 一行 + 一个披露 + 一个主动作；督战点击仍开速览；
  产物锚仍开速览；「想调整」逃逸口在；空态/composer 不回归。
- **e2e 消费者（必原子处理）**：
  - `m9_guide_loop_acceptance.py`：`.plan-card`（可见）· `.agent-status`（≥1 + "排队中"）·
    `.status-artifact`（"1 件产物" + 点击开速览）。→ **保留这三个 class 名与语义**（减重在其内部结构，
    不改这三个承重锚），或同批更新断言 + 重截图。**优先保留 class 名**降低契约扰动。
  - `m6_guide_acceptance.py`：`.hero-title`「说说你要做的工程活儿」+「导引不会替你创建」字面 → 不触碰。
- **风险**：低（纯前端，锚可保留）。

### 批 2 — 任务台并入状态中心（动作 2）· 中风险
- **验收**：一级导航仅「对话」；`/tasks`·`/tasks/:id`·`/workbench` 深链全兼容（可刷新/回退）；
  StatusCenter inbox 底部「查看全部任务 →」达 `/tasks`；待签/在跑总览从状态坞可达。
- **e2e 消费者（必原子重立，safe-refactor 核心）**：
  - `m8_workbench_acceptance.py` ①：`nav_texts == ["对话","任务台"]` → 改 `== ["对话"]` + 重截图；
    ②④：`.nav-link.is-active == "任务台"`（/tasks、/:id 视图高亮）→ 无 任务台 nav 项后改为断言
    「对话高亮」或改走「状态坞可达 + 深链渲染」新契约；②`/workbench→/tasks` 重定向断言保留。
  - `m8_collab_chain_acceptance.py`：⑦ redirect + 侧栏断言含 任务台 → 同步重立。
  - `m6_guide_acceptance.py`：line 146 任务台 nav 注释/断言 → 校对。
- **风险**：中（改导航契约=祈使句级 IA 动作；照 Phase 2b 先例，e2e 契约与骨架同批原子交付）。
- **纪律**：动手前过 skill `safe-refactor`，穷举全部 `.sidebar-nav` / `nav-link` / 任务台 消费者
  （含上表 + App.vue `activeMenu` 逻辑）。

### 批 3 — 任务详情速览优先（动作 3）· 中风险
- **验收**：所有默认点击路径落速览（无一甩整页）；速览签发就地闭环（`POST /tasks/{id}/review`
  同一端点，人具名 fail-closed）；「查看完整页 →」深链在；整页深链态二次密度清理不破坏其自身
  e2e（TaskConsole 三栏 / TaskDetail）。
- **e2e 消费者**：`m8_workbench`（TaskConsole 三栏渲染 + 到席灯中性墨色级断言）·
  `m9_guide_loop`（速览直达）· `m2_acceptance`（详情事件/签发）→ 逐一校对速览优先后不回归。
- **风险**：中（速览基建已在，主要是默认路径改道 + 整页深链态清理的回归面）。

### 批 4 — 全局密度纪律收尾（动作 4 残项）· 低风险
- **验收**：逐屏「一屏一主动作」巡检；留白/次要控件/冗余文案清理；无 e2e 锚字面改动。
- **风险**：低。

## 六、焊死红线（不减项）

- **信任色锁**：clay 工作 / amber 待签 / teal 人签 / 绿 仅真实 / 中性 完成——五槽不增不改；
  注意力信号（未读）继续用形状+字重零新色（Phase 2c 裁例）。
- **诚实地板**：「导引不会替你创建或签发」「签发权在你」「无证据不标 / 不装有数据」全承袭；
  速览产物失败诚实报错不空白假装。
- **人是唯一发起者**：Agent 选择器/意图卡只填草稿绝不代发；签发只走人具名 `POST /review`。
- **祈使句 6 真流非表演**：所有计数/状态来自真实轮询，pill 数字绝不估算。
- **e2e 不裸奔**：任一契约变更（尤批 2 导航、批 1 方案卡锚）与实现原子同批；`verify_all` 八步门全绿。

## 七、决策记录（两个结构性选择）

1. **批 2 删导航 vs 删路由**：**删导航入口，保留 `/tasks` 路由**（祈使句 5 明定路由全保留；
   治理全量总览经 StatusCenter「查看全部 →」深链可达）。比「彻底删整页」更可逆、保治理价值——
   且这正是范式所要求，非仅更稳。
2. **批 3 签发放速览**：认可。速览内联签发是 Phase 1 已交付基建（祈使句 4），走同一
   `POST /tasks/{id}/review` 人具名端点，非新承重面。

## 八、验证策略

- 每批：前端 build + `verify_all.sh` 八步门（前端 build + 三 testpaths pytest + 6 套 e2e 全绿 exit 0）。
- 批 2 额外：headless 双 Surface→单入口走查 + 深链刷新/回退实测（`/tasks`、`/tasks/:id`、`/workbench`）。
- 密度自证：改动前后同屏控件计数对照（85→目标 ≤~35；单卡 11→≤~4），截图 before/after 归档
  `docs/reviews/`。
- 诚实地板/信任色锁**颜色级**真咬合断言承袭（非仅可见性）。

## 九、边界与非目标（YAGNI）

- 不改后端契约、不加路由、不引新依赖/框架/状态库（纯前端密度与 IA 层）。
- 不做整页 TaskDetail 的彻底重写（只深链态二次清理，全量重构非本轮）。
- 不碰 Phase 2c 递延项（中断-恢复一等条目——需后端 retry/resume 契约先立）。
- 不新增颜色槽 / 不改信任语义 / 不动 MOTION-SYSTEM 动效层。
- 不引入日期/调度门控；批次门只看依赖（批 2/3 依赖批 1 的对话主轴清爽，可顺序推进）。
